# 测试计划（用户管理系统）

| 项目 | 内容 |
|---|---|
| 被测系统 | 用户管理系统（登录 / 注册 / 用户列表） |
| 版本 | v1.0 |
| 测试类型 | 功能测试 + 接口测试 + 自动化冒烟测试 |
| 测试周期 | 4 周 |
| 编写人 | （你的名字） |

---

## 1. 测试目标

验证用户管理系统的核心功能是否符合需求，重点保证 **注册**、**登录**、**用户列表** 三条主流程的正确性，并尽可能发现缺陷，输出可复用的自动化脚本。

## 2. 测试范围

### 2.1 范围内（In Scope）

| 模块 | 功能点 |
|---|---|
| 注册 | 用户名 / 密码 / 确认密码 / 邮箱 四项输入的合法性校验、重复用户名拦截、注册成功后跳转登录 |
| 登录 | 正确登录、用户名不存在、密码错误、空值提交、登录态维持、退出登录 |
| 用户列表 | 登录后可查看、未登录跳转登录页、列表数据正确性 |
| 接口 | `/api/register`、`/api/login`、`/api/users` 的请求/响应、状态码、异常入参 |

### 2.2 范围外（Out of Scope）

- 密码找回、验证码、第三方登录、多因素认证
- 权限分级（管理员/普通用户）
- 性能测试、安全渗透测试、兼容性测试（多浏览器）

## 3. 测试环境

| 项 | 配置 |
|---|---|
| 操作系统 | Windows 11 |
| 后端 | Python 3.11 + Flask 3.x |
| 数据库 | SQLite |
| 浏览器 | Chrome（最新版） |
| 测试工具 | pytest、requests、Postman |

## 4. 测试策略

1. **功能测试（手工为主）**：依据需求，用「等价类划分 + 边界值 + 场景法」设计用例并逐条执行，重点覆盖注册、登录两个模块。
2. **接口测试**：用 requests / Postman 验证接口的入参校验、状态码、返回结构。
3. **自动化测试**：用 pytest 将核心接口用例脚本化，实现一键回归，作为加分项。

## 5. 准入 / 准出条件

- **准入（什么时候开始测）**：被测系统可正常启动，数据库可初始化，核心接口能返回响应。
- **准出（什么时候算测完）**：
  - 功能测试用例执行率 100%，通过率 ≥ 95%；
  - 无「严重」及以上未解决缺陷；
  - 冒烟测试与核心接口自动化脚本全部通过。

## 6. 进度安排

| 周次 | 内容 |
|---|---|
| 第 1 周 | 需求梳理 + 环境搭建 + 冒烟测试 |
| 第 2 周 | 用例设计 + 功能测试执行 + 缺陷记录 |
| 第 3 周 | 接口测试 |
| 第 4 周 | pytest 自动化 + 测试总结 |

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 时间紧、需求理解不深 | 优先保证登录/注册核心用例，其余模块做精简覆盖 |
| 自动化经验不足 | 只做接口层的少量自动化，不追求 UI 自动化 |
