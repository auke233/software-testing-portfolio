# 接口测试文档（用户管理系统）

## 一、HTTP 基础速记

| 方法 | 作用 | 示例 |
|---|---|---|
| GET | 查询，参数在 URL | `/api/users` |
| POST | 新增/提交，数据在请求体 | `/api/register` |
| PUT | 更新 | `/api/user/1` |
| DELETE | 删除 | `/api/user/1` |

**常用状态码：**

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 201 | 创建成功（注册用） |
| 400 | 请求参数错误 |
| 401 | 未认证 / 密码错误 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

**请求/响应常用格式**：JSON。请求头用 `Content-Type: application/json` 告诉服务器「我发的是 JSON」。

---

## 二、接口清单

| 接口 | 方法 | 请求参数 | 成功响应 |
|---|---|---|---|
| `/api/register` | POST | username、password、email（JSON） | 201，`{"code":0,"msg":"注册成功"}` |
| `/api/login` | POST | username、password（JSON） | 200，`{"code":0,"msg":"登录成功","data":{...}}` |
| `/api/users` | GET | 无 | 200，`{"code":0,"data":[...]}` |

错误响应统一为 `{"code":1,"msg":"错误原因"}`，状态码随错误类型变化（400/401）。

---

## 三、用 curl 手动测（命令行）

```bash
# 注册
curl -X POST http://127.0.0.1:5000/api/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test01","password":"abc123","email":"t@x.com"}'

# 登录
curl -X POST http://127.0.0.1:5000/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test01","password":"abc123"}'

# 查用户列表
curl http://127.0.0.1:5000/api/users
```

## 四、接口测试「测什么」

1. **入参校验**：缺字段、字段类型错、边界值、非法字符 —— 是否返回 400 + 明确错误提示。
2. **状态码**：成功/失败时返回的状态码是否正确（201 vs 400 vs 401）。
3. **返回结构**：字段是否齐全、类型是否正确（`code`、`msg`、`data`）。
4. **异常场景**：请求体非 JSON、超大参数、重复数据。
5. **业务逻辑**：密码错误 → 401、重复注册 → 400、登录成功 → 返回 username。
